## What 0.1.0 means

Four proofs, all true:

1. One public bug, on a repo this runner did not grow up beside, is killed by tests that were already in that repo. The revealing test stays hidden. The label stays out of the JSON. Two runs agree.
2. A normal pytest, Node, Go, or Java repo needs no hand setup. One documented install, then one Probatio command. The line map chooses the tests for the lines that changed. `verify-change` uses that same map.
3. The tally keep list is a set of ids the next run can execute, for pytest, Go, JUnit, Cargo, and dotnet. `deletedTests` stays 0.
4. A clean machine runs the npm tarball, not `tsx src/cli.ts`, and gets the same JSON fields.

## What 0.1.0 does not mean

- It does not replace unit tests.
- It does not fail CI on a kill count.
- It does not catch a bug the suite has never asserted. If the sealed run misses, that miss is the result. Do not restore the hidden test and score again.
- It does not add a worker pool, a wider operator set, a COBOL corpus, an assembly corpus, or an AMD64 bugscpp image.
- Each mutant keeps its own process.
- C, C++, and COBOL stay "the project's own suite, or a refusal."
- A line that runs only in a child process stays `no coverage`.

## 1. A sealed catch on a stranger repo

The command is already shipped. This section is the evidence, plus any small product fix the evidence forces. A hand-planted bug in a fixture, Auspex, markupsafe, and the old tqdm cut do not count.

### 1.1 Pick the subject before spending a sealed run

A subject is eligible only when all of these are true:

- The repo is public and under an OSI license.
- This runner's authors did not write its tests for Probatio.
- The fixed commit is green with the project's own test command.
- One revealing test can be named as a path and hidden with `--hide`.
- The bug is a forward patch that applies onto that fixed commit. The patch is the inverse of the upstream fix, or a minimal hunk of it. It is not a fresh operator mutant invented for the demo.
- `bug_id`, `issue_id`, and `expected_fail` live only in the label file. Those strings are absent from the source, the patch, and the test names.
- Hiding the revealing test and applying the bug makes at least one older test fail. If the suite is still green, the suite never saw the bug. Record that in one line and do not start `mutate sealed`.

Search in this order. Stop at the first eligible subject. Cap the search at five recorded ineligible or missed subjects.

## 2. A normal repo, no hand setup

Flask's timing does not count. It needed a side directory of dependencies and a metadata install. No nose shim. No JDK pin script. No deleted tests. No `--suite-command` that wraps the suite in a one-off shell.

Supported languages for this section: pytest, Node (`node:test` or Mocha as discovered), Go, Java (Maven, JUnit 4 or 5). One repo each is enough. Each suite is green and has at least a few hundred tests, or the largest green suite under a few hundred that still uses the line map to run a handful.

## 3. Keep lists the next run can execute

A keep id that pytest, `go test`, Maven, Cargo, or `dotnet test` cannot collect is a bug, even when the summary says killed. `--suite-command` is not the rescore. That path is kind `command` and the kill is `::command`.

### 3.1 An id the runner accepts

`RunOptions.onlyTests` exists and is not a CLI flag. `check-kill` uses it for importers.

- [x] Add a repeatable `--only-test <id>` on `mutate run`. It sets `onlyTests` and still discovers the suite kind. Done when a builder test passes the tally keep id back through the CLI and the suite kind stays pytest, go, maven, cargo, or dotnet.
- [x] Reject `--only-test` combined with `--suite-command` in one run. Done when the CLI returns `ok: false` and starts no mutant.
- [x] `mutate tally` prints `nextCall` as that `mutate run` with the keep ids. Done when the argv in the tally JSON is a command that collects, and `deletedTests` is 0.

### 3.2 One builder test per language

Each test plants one kill, tallies, and runs the keep id through `--only-test`. The test fails if the id is doubled, prefixed with an empty `::`, or rejected by the tool (pytest exit 4, go/maven/cargo/dotnet collecting nothing).

- [x] Pytest. The existing node-id test stays. Extend it so `--only-test` of the keep id kills the same mutant. Done when the keep id equals `killedBy` and pytest collects it.
- [x] Go. `killedBy` is the name `go test -run` accepts. Done when the rescore command contains `-run` and the test fails.
- [x] JUnit. `killedBy` is the `-Dtest` selector, including parameter types when Surefire needs them. Done when a parametrized method is not truncated to a name Surefire refuses.
- [x] Cargo. `killedBy` is the exact test name. A leading `::` with an empty file fails the new test. Done when `cargo test <id> -- --exact` is the command and the name is not `::test_name`.
- [x] dotnet. `killedBy` is a `--filter` the same `dotnet test` accepts once, not the name repeated once per target framework. Done when one filter run kills, and the keep list does not list the same method three times unless they are three different tests.

### 3.3 Rescore the real keep list

- [x] On the pytest repo from section 2, tally a killed mutant and run `--only-test` for every keep id, twice, in fresh out dirs. Done when both summaries kill the same mutant, the commands contain only keep ids, and `deletedTests` is 0.
- [x] Repeat for whichever of Go or Java section 2 actually killed a mutant. Done when that rescore agrees twice. If both survived, say so and do not invent a kill.
